# ADR-0001: Technology stack and dependency policy

Status: accepted (2026-11-14)

## Decision
- Backend: Python ≥3.10 (dev on 3.11), FastAPI, Uvicorn, Pydantic v2, websockets.
- Data: PyArrow (CSV/Parquet/JSON streaming), ijson (JSON arrays), Hugging Face `datasets` streaming, Polars available for column statistics; SQLAlchemy only as an optional `db` extra for future connectors (keyset pagination / server-side cursors, never OFFSET).
- Training: PyTorch, Transformers, PEFT, TRL, Accelerate; Unsloth + bitsandbytes on CUDA (`gpu` extra).
- Monitoring: psutil, torch.cuda, NVML via `nvidia-ml-py`.
- Frontend: React + TypeScript + Vite + Tailwind + Radix primitives (shadcn-style), TanStack Query, Recharts.
- Testing: pytest, pytest-asyncio, HTTPX/TestClient, vitest + testing-library.

## Dependency policy
`pyproject.toml` uses lower bounds only. Colab and Kaggle preinstall torch/transformers matched to their CUDA; pinning exact versions there would force incompatible reinstalls. Exact versions verified on the dev box are recorded in `requirements/verified-dev.txt` (generated by `uv pip freeze`). Heavy packages are imported lazily.

## Consequences
GPU dependency combinations on Colab/Kaggle are validated by running the notebooks there (UNVERIFIED until done).
